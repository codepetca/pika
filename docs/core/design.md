# Pika UI/UX Design Guidelines

> Compatibility redirect: the canonical Pika design entry point is
> [`DESIGN.md`](/DESIGN.md).

This path remains as a short redirect for older internal links. Do not add new
design guidance here.

For UI work, read:

1. [`DESIGN.md`](/DESIGN.md) for global principles, authority, foundations,
   ownership, and governance.
2. [`src/ui/README.md`](/src/ui/README.md) for canonical component APIs and
   semantic-token usage.
3. [`docs/guidance/ui/README.md`](/docs/guidance/ui/README.md) for stable,
   family-specific, experimental, legacy, and open-question guidance.
4. [`docs/guidance/ui/change-brief.md`](/docs/guidance/ui/change-brief.md) before
   non-trivial user-visible work.
5. [`docs/guides/ai-ui-testing.md`](/docs/guides/ai-ui-testing.md) for visual
   verification.

Executable values and behavior remain owned by:

- [`src/styles/tokens.css`](/src/styles/tokens.css)
- [`tailwind.config.ts`](/tailwind.config.ts)
- [`src/ui`](/src/ui)

Historical examples previously stored here were removed because they duplicated
or contradicted the semantic-token and shared-component system. Use Git history
only when investigating their provenance.
