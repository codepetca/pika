# Pika product, design and architecture audit — 2026-11-17

## Decision

Preserve Pika's shared classroom shell, semantic design system, operational-table patterns and guarded server contracts. Prioritize correctness and accessibility gaps in existing workflows, then separate asynchronous ownership in the largest coordinators. A replacement design system or broad rewrite is not justified by this audit.

This is dated audit evidence for the existing `epic-product-experience-architecture` and its [six-phase roadmap](product-experience-audit-2026-07.md#execution-backlog). It does not promote a new stable design, mark that epic complete, or authorize implementation, migration application, production writes, publication or rollout.

## Design direction and reuse decisions

The sampled teacher Classwork/Tests surfaces share a recognizable card/shell family. Attendance retains a quiet, scan-friendly operational table. Gradebook already changes to a selected-student detail composition on mobile; the old “narrow-screen navigation deferred” statement must not be read as absence of all mobile support. Student Classwork is readable in both themes and has more descriptive card names than the teacher equivalent. The mobile navigation drawer provides a named, focused shared modal reference.

Consistency work should make these interaction guarantees dependable. It should preserve the different purposes of teacher scanning, student completion, writing, authoring and grading.

| Need | Existing candidate | Decision | Reason |
|---|---|---|---|
| Roster dialog semantics and lifecycle | DialogPanel/ContentDialog, backed by ModalLayer | reuse | The behavior already exists; keep roster parsing and requests feature-owned. |
| Roster field errors | Existing parser result and field/error association | extend | Add location/reason to the current workflow without a second import wizard. |
| Calendar dates | Existing class-day button | extend | Full date names are domain-specific; no new calendar widget is needed. |
| Archive action target | IconButton | reuse | Canonical action geometry fits; preserve its feature callback. |
| Reorder handle target | Existing dnd-kit sortable owners | extend | Enlarge hit geometry while keeping keyboard/listener semantics feature-owned. |
| Card triage metadata | Existing assignment/survey/test card owners | extend | Improve accessible metadata while preserving distinct status semantics. |
| Partial Classwork availability | Existing list load-state owner/PageState | extend | Only if independent-source behavior is worth the additional state contract. |
| Async coordinator separation | Existing scoped request/controller patterns | extend | Establish explicit ownership; avoid a generic universal classroom controller. |

No `create` decision is warranted for a new shared visual primitive yet. The sort-handle portion of U5 must extend its current owner rather than force IconButton to absorb dnd-kit behavior. No stable token, theme or global design-rule changes are proposed.

## Sequence within the existing roadmap

These are proposed work packets within the July phases, not a second roadmap or implementation already performed. Each packet needs its own scoped branch, review and relevant checks.

1. **Grade evidence integrity — Phase 4 / Safety Wave:** A4 first, then A3 using one complete, typed history-read contract. Exit: failures cannot produce grades; complete history produces equivalent scores; real successful-empty policy remains intact. Effort: medium.
2. **Roster entry — Phase 3 / Phase 2 adoption:** U1/U2/U6 together in one vertical workflow, reusing canonical dialog behavior and preserving all typed rows. Exit: no silent contact loss, row-specific feedback, keyboard/busy matrix and affected teacher desktop/mobile/light/dark screenshots. Student role is n/a for the dialog, with access denial retained. Effort: small–medium.
3. **Legacy mutation parity — Safety Wave / Phase 3:** A2 and A6 as separate domain slices, using A7 schemas as appropriate. Exit: database-backed conflict/rollback/idempotency regressions plus legacy/contextual/Pal parity. Any migration requires exact-target authorization. Effort: medium per slice.
4. **Access-policy reconciliation — Phase 5 / Phase 6:** resolve A1's own-retained-data policy and test every signing path against it. Exit: explicit contract and denial/success matrix, without changing cohort rollout implicitly. Effort: small–medium after policy resolution.
5. **Semantics and control adoption — Phase 3:** U3/U4/U5/U7 in small family-owned slices. Exit: date/card accessible names, actual 44px bounds, reorder keyboard behavior, reduced-motion checks and targeted visual comparisons. Effort: small per slice.
6. **Async ownership and history — Phase 3 / Phase 6:** S1/S2/S3 one extraction at a time; A5 separately because it affects persistent history. Exit: fixed-owner tests, late-response/cancellation proof and revision-ordered history recovery. Effort: medium; A5 may need schema work.
7. **Evidence/backlog hygiene — Phase 6:** S4/S5/S6 and U8 only if justified by measured failure incidence. Preserve completed mobile/authoring/error-state work. Exit: current finding statuses, authoritative ownership links and a route/state evidence matrix with honest gaps. Effort: small for docs, medium for uncovered workflow verification.

Recommended first implementation: grade evidence integrity, with roster entry independent enough to proceed alongside it under separate file ownership. No speculative new infrastructure is necessary.
